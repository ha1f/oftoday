# 用語集

oftoday で使う言葉と、コードでの名前をそろえるための文書。新しい語は、議論で決めた時点でここに足す。

## 用語

| 用語 | コードでの名前 | 意味 | メモ |
| --- | --- | --- | --- |
| 投稿 | `Post` | SNS に載せるもの。流れて消えず、後から価値が増えていく | 「記録」とは呼ばない |
| 認識 | 未定 | 撮ったものを AI が読み取ること | |
| 特徴 | `TraitKey`・`TraitValue` | カテゴリごとに決まった項目（`TraitKey`）と、その値（`TraitValue`） | 単体の `Trait` は Swift Testing の型と同じ名前になるので使わない |
| カテゴリ | 未定 | どんな特徴を持つかを決める単位。カテゴリごとに特徴の一覧を持つ | |
| 注釈 | `Annotation` | 認識の上に人が重ねるもの。注釈で次の認識が賢くなる。種類は修正・確認・感想で、`Annotation.Kind` の case にする | MapKit にも `Annotation` がある。地図を描くファイルでは `MapKit.Annotation` と書く |
| 図鑑 | `Catalog` | 撮った対象ごとに、みんなで育てる情報の集まり。中の 1 件は `CatalogEntry` | 「辞書」とは呼ばない（`Dictionary` と紛れるため） |
| 切り口 | `Lens` | 投稿をどう集めるか。今日の（of today）、人生で一番の（of life）、行事の（ハロウィンの）など | どの切り口を使うかは、vision.md のとおりまだ決めていない |
| お題 | `Topic` | 切り口とカテゴリの組み合わせ。「今日の夕食」「人生で一番の夕食」「ハロウィンのお菓子」など | `Prompt`（FoundationModels の型）と `Theme`（UI のテーマと紛れる）は使わない |

## まだ決めていないこと

### 認識とカテゴリのコードでの名前

まだ案が無い。

### 特徴の値の出どころ

特徴の値ごとに、何が埋めたか（写真の文字、AI の推測、図鑑、人）と、人がどう関わったか（そのまま保存した、直した、わからないと答えたなど）を持つ案がある。注釈の「修正」「確認」と重なる部分があるので、持つかどうかと名前は、データの形を決めるときに決める。

### そのほかの候補

写真（`Photo`）と画像ベクトル（`ImageEmbedding`。Vision では feature print と呼んでいる）。今のところ、ほかの名前と食い違う点は見つかっていない。

### サービス名

候補は 3 つ。商標とドメインはまだ調べていない。

- oftoday: 「〜 of today」「〜 of life」と、切り口の形がそのまま名前になる。of life などに広げると、名前が狭く感じるかもしれない
- Of: 切り口の共通部分だけを取る。短いが、検索で見つけにくい
- Strata（地層）: 注釈が層になって積もる、積み上がる SNS のイメージ
